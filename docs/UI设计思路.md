# UI 设计思路

> 这份文档回答一个问题：这一版界面为什么长成这样。
> 它不是功能清单（功能见 `0.14.6-动效与纹样系统.md`），而是**判断依据**：每个视觉决定背后
> 参考了什么、放弃了什么、用什么数据确认它成立。

---

## 一、核心主张

**把"工具界面"做成"一份被反复翻看的旧图纸"。**

Stronghold Link 是联机隧道控制台：用户真正要做的事只有几件（开会话、进会话、看状态、拉好友）。
所以界面不承担"吸引注意力"的任务，它要承担的是**在长时间挂机时仍然耐看、不吵、不抢焦点**。
由此推出三条贯穿全篇的原则：

1. **信息永远优先于装饰。** 装饰可以退、可以让位、可以在窗口失焦时完全停下，但状态、端口、
   错误原因必须永远可读。所有装饰层都在内容之下。
2. **动是有理由的，不是有存在感的。** 每个动画回答一个具体问题：这一屏刚进来（所以有入场）、
   用户切了页（所以有方向性转场）、焦点在哪（所以有游标与高亮）、系统还活着（所以有呼吸与扫描）。
   没有"看起来很高级所以一直晃"的东西。
3. **一切可测量。** 帧时间、p95、内存曲线、像素占比、控件尺寸——任何"更顺了/更清楚了"的判断
   都必须有数字，不靠肉眼宣称。

## 二、参考系：学什么，不学什么

参考是《明日方舟》六周年 PV 的动态设计语言。**学的是运动逻辑与界面语汇，不是画面本身。**

| 学的 | 具体落地 |
|---|---|
| 快出缓收 | 转场 320–560 ms，`OutExpo/OutQuint` 收尾；按钮按下 120 ms |
| 斜切语汇 | 色块是平行四边形（`SKEW = -0.20`），没有纯矩形高亮 |
| 擦除揭示 | 内容不是淡入，是被一条硬边"擦"出来，前沿压一道更亮的细线 |
| 运动分层 | 主体先动、装饰后跟（`STAGGER 48 ms`），镜头与内容不同层 |
| 结构先于细节 | 先有大圆、轴线、点阵、量测刻度，再放主体 |

| 不学的 | 原因 |
|---|---|
| 霓虹渐变 / 玻璃拟态 | 与"旧科研图纸"的气质相反，且在高分屏上廉价 |
| 3D 粒子 / 大量光斑 | 成本高、遮挡信息、在挂机场景下变成噪音 |
| 逐帧复刻 PV 镜头 | 那是视频语法，桌面软件里的镜头必须可中断、可反向、可回滚 |
| 大块纯金、过曝、重描边 | 用户明确禁止；金色只作为"极少量标记"存在 |

**用户给出的硬约束（优先级高于我的偏好）**：不要 UI 相互遮挡；小分辨率下不能什么都看不清
（所以缩放下限从 1.0 降到 **0.72**）；鸟要多、要浩浩荡荡、不能只有一列；
参考图的鸟型要"照着抄"而不是"画个像的"；轮廓要清晰但不要粗。

## 三、视觉语言

### 3.1 色彩

不是"配色表"，是**角色分工**：

| 角色 | 取值 | 用法 |
|---|---|---|
| 纸面 | `#e9ecec` / `#eff1ef` | 大面积底色，接近白，略有灰绿冷调 |
| 墨 | `#22282b` | 正文与关键数字，唯一"近黑" |
| 钴蓝 | `#3a5bc2` | 结构线、圣徽、轴线；也是唯一"饱和"色 |
| 冰蓝 | `#4c92d4` | 次级结构、量测弧 |
| 银灰 | `#9aa1a5` / `#c2c8ca` | 分隔线、次要标注 |
| 香槟金 | 极少量 | 只用于"当前状态"的记号，不做大面积 |

规则：**同一屏最多一个饱和色域**。所有颜色都走 `theme.js` 令牌，不散落在 QML 里；
8 位色必须写 Qt 的 `#AARRGGBB`（写 CSS 的 `#RRGGBBAA` 会出现黄绿线，这是本项目踩过的坑）。

### 3.2 线条与材质

- 零位图：全部 Canvas / Shape 矢量绘制，天然支持任意缩放与高分屏。
- 线宽统一走 `lw(base) = clamp(base*PX, 0.7, 1.9*PX)`，`PX` 由屏幕实际缩放比反推 —— 小窗口下
  线不会细到消失，大窗口下不会糊成一片。
- 透明度统一走 `alpha()`，并带一点屏幕补偿（`VIS = 1.55`），避免缩小后整体发灰。

### 3.3 字体与文字

- 中文标题用衬线（Songti 系），数字与标注用等宽（Consolas）——"图纸上的字"就是这种分工。
- 文档里不允许出现乱码 / 占位符 / U+FFFD；测试里有专门断言防回归。
- 角落里的小注（`SH / FIELD RECORD · VOL. 04`）是**真实文字**，不是假字形——它承担"这是
  一份档案"的叙事，同时给版面右下角配重。

### 3.4 构图：四套模板 + 一个主导母题

每屏只允许**一个主导母题**，其余元素服从它：

| 模板 | 母题 | 用途 |
|---|---|---|
| A | 淡纸面 + 三股鸟潮 + 圣徽留白 | 常规页主视觉 |
| B | 穿孔拱 + 鸟群穿行 | 好友页（人数=鸟数，功能与视觉同构） |
| C | 同心刻度环 + 密集鸟群 | 设置页（参数感） |
| D | 玫瑰窗（转场专用） | 页面切换 |
| E | 白底 + 参考图矢量笔画 + 环状花纹 | 会话页主视觉（用户指定形态） |

留白是结构的一部分：左侧蓝块右侧 0–0.10w 不放东西，右上角留出放射线的空隙——
"空"让"密"成立。

## 四、版面与信息架构

- 设计基准 1680×1240，等比缩放到窗口；`minScale 0.72` 是硬下限（再小字就不清了），
  上限 1.8（2560 屏铺满）。
- 标题栏与边注**不参与版面缩放**（`CHROME_H = 40`），保证任何缩放下都清晰、可点。
- 三页固定，不新增路由；导航顺序、焦点顺序不动。
- 题词那一行 `z: 1300` 必须在自绘标题栏（`z: 1200`）之上——这是被"整条被盖掉"教训过的地方，
  现在有测试盯着。
- 装饰层一律 `enabled: false` + 内容之下：**任何情况下不吃鼠标、不挡控件、不做几何约束**。

## 五、动效系统

### 5.1 时间基准

- 所有 QML 动画走墙钟，与帧率无关。
- 唯一的"自驱动"相位（鸟的滑翔）**按真实经过时间推进**：`phase += dt/1000 * phaseSpeed`，
  单帧间隔钳制 400 ms，Timer 停止时清基准 —— 掉帧不变速，暂停回来不跳相。
- 失焦 / 最小化：`animating = awake && active` 一道总闸，装饰全停，**但状态轮询继续**
  （数据要新鲜，画面不必在看不见时空转）。

### 5.2 缓动语义（不是一套曲线打天下）

| 用途 | 曲线 |
|---|---|
| 位移、入场 | `OutCubic` |
| 擦除、推进 | `OutQuint` |
| 循环呼吸 | `InOutSine` |
| 硬切转场带 | `OutExpo` |
| 受控过冲（仅按钮回弹） | `InOutBack`，幅度 ≤ 3% |
| 匀速循环漂移（扫描带/尘埃带） | `Linear`（**只允许这两处**：用缓动反而会在环缝处顿一下） |

### 5.3 错峰与节奏

- 同页部件逐个入场：`STAGGER 48 ms`；面板擦除：`STAGGER_WIPE 55 ms`。
- 延迟由"主→辅"的运动关系推出，不是随机抖动：位置越远、延迟越大；装饰比主体晚半拍。
- 鸟群每只的往复周期是 `5200 + (i%8)*620 ms`（x）/ `4800 + (i%6)*540 ms`（y）——
  **同源不同相**，看起来才像一群鸟，而不是一张图在抖。

### 5.4 镜头与视差

- 四层视差：背景 ±22/14、版面 ±6/4、边注 ±34、定位十字 ∓26/20。幅度小、方向协调。
- 切页有一次 260 ms 的镜头顶动（`OutQuint`），到点收束，不做持续晃动。
- 12 秒呼吸：整体 ±0.6% 缩放 + 亮度微变，让人感觉"界面在呼吸"而不是"在动"。

### 5.5 转场三阶段

擦除 → 斜切带扫过 → 玫瑰窗（模板 D）。开始/进行/结束都完整，可中断、可反向；
连续快速切页不会留下残影或错误终态（模板 D 的可见层固定 `animateReveal:false` +
`Canvas.Immediate`，否则中间值会被 Canvas 合并重绘吞掉）。

## 六、性能纪律

- 目标 60 fps（16.67 ms）。实测稳态 **p95 ≈ 13.8–17 ms**，无掉帧尖峰。
- 成本分层：远景/小尺寸鸟走廉价档（不画柔光体、不 bloom、10 段采样）；点阵 24 列而不是 46 列；
  鸟越界镜像折回（不再有被裁掉却照样吃重绘的鸟）。
- **静态的东西不许有心跳**：模板 E 画完即静止 → `hasMotion = false`，不跑常驻重绘
  （单次 72 组多边形很贵）。
- 常量：常驻画布 10 fps（不是 60）；静态层只在显现/尺寸变化时画一次。
- 内存实测：会话页 255 MiB、好友页 282 MiB、设置页 267 MiB，30 秒级观测平稳；
  曾出现"会话页 24 秒 272 → 469 MiB 单调上涨"，根因是缩放比逐帧比较导致静态图版逐帧重绘，
  修法是**量化到 0.05 一档再比较**，并有测试盯住。

## 七、怎么验证（没有眼睛的时候）

我的运行环境读不到图像，所以视觉结论全部靠**可复现的测量**：

| 想确认 | 方法 |
|---|---|
| 鸟有几只、铺得开不开 | `tools/bird-count.cjs`：stub canvas 数 `destination-out`（每只鸟一次）+ 位置统计 |
| 某个区域到底画了没有 | 抓图后用 PIL 统计亮度分布/深线像素占比（并**按 alpha 掩膜**，否则 RGBA 透明像素会被误判成黑块） |
| 布局有没有被动过 | 同尺寸前后抓图逐区域像素差分 + 控件树尺寸 |
| 动画是否真的在画 | `--perf` 帧时序 + 日志里 `t` 值序列（曾被 Canvas 合并重绘骗过一次） |
| 内存有没有漏 | 每 2 秒采样 WorkingSet，看首尾均值与曲线形状，不看单点 |

## 八、踩过的坑（都变成了测试或文档）

1. **`#RRGGBBAA` vs `#AARRGGBB`**：26 处 8 位色写成 CSS 顺序 → 屏幕上出现黄绿线。现在有断言。
2. **Canvas 合并重绘**：`Canvas.Cooperative` 会把一串 `requestPaint` 合并，动画中间值被吞；
   需要真中间态的层必须 `Canvas.Immediate`。
3. **`ShapePath` 没有 `opacity`**（Qt 6.8）：透明度要烘进 `strokeColor` 的 alpha。
4. **`QtQuick.Shapes` 模块没部署**：`module not installed` → 发布包必须补 `Qt6QuickShapes.dll`
   与 `qml/QtQuick/Shapes`（已在发布脚本里自动补）。
5. **缩放比逐帧比较**：静态图版变成逐帧重绘 → 内存单调上涨（见上）。
6. **像素描摹的碎片**：从截图矢量化出来的鸟放大后"断断续续"；正确做法是膨胀闭合断口后
   取外轮廓，用细线（`stroke-width 1.15`）重描，而不是继续调色/加粗。

## 九、被否决的方案（以及为什么）

| 方案 | 否决理由 |
|---|---|
| 运动模糊 | QML Canvas 没有便宜实现（要么离屏两次再重采样、要么上 shader），代价与收益不成比例；改用"擦除前沿亮线 + 线宽"表达速度 |
| 景深模糊 | 只有分层位移视差，没有深度信息；且父项非 1 的 opacity 会让 Qt 开离屏纹理，代价高于观感收益 |
| 更密的鸟群（138 只） | 实测掉到 37.7 ms/帧（18 fps），用"廉价档 + 79 只"折中 |
| 每只鸟单独轮廓 + 内部细节 | 膨胀闭合会把细节并进外轮廓；两者都要需再做"内部主线条"单独描一遍，成本另算 |
| 读系统 reduce-motion | 目前用的是项目自己的动效档位（完整/标准/最低），够用且可控；系统级开关留作后续 |

## 十、如果要继续做，我的排序

1. **打包链路补 `QtQuick.Shapes`**（已在 `tools/shl-release.cjs` 里补，还需回灌 `pack-qml.cjs`）。
2. **多分辨率验收**：1280×720 / 1920×1080 / 极窄窗的逐图核对（目前只覆盖 1440×900 与 1024×720）。
3. **点击穿透的自动化验证**：现在只有 `enabled: false` + z 序证据，缺真实鼠标脚本。
4. **鸟型"外轮廓 + 内部主线条"双轨**：既要整体剪影的连贯，又保留图纸感的分缝。
5. **系统 reduce-motion 读取**：把 OS 级无障碍开关接到 `motionTier` 上。
