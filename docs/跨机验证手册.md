# 跨机验证手册

这些验证需要**两台真实机器**（Steam 那项还需两个账号），本机无法替代。下面每条都给出可复制的命令与"要记录什么"，结论请回填到文末表格。

## 0. 准备

- 两台机器都拿到代码：`git clone` 后 `npm install`，或直接用便携版
- 先跑本机自检确认基础链路：`node --test --test-isolation=none test/relay-selftest.test.cjs`
- 记录两台机器的网络环境（家宽 / 公司网 / 手机热点），NAT 行为差别很大

## 1. 打洞验证（Direct UDP 真实通路）

机器 A：

```powershell
node tools/punch-one-shot.cjs host
```

打印形如 `本机公网映射 = 1.2.3.4:57243`，把这一行发给 B。

机器 B（用 A 的映射）：

```powershell
node tools/punch-one-shot.cjs joiner 1.2.3.4:57243
```

B 也会打印自己的映射，发回给 A。A 再跑一次并带上 B 的候选：

```powershell
node tools/punch-one-shot.cjs host <B的公网地址:端口>
```

| 要记录 | 结果 |
| --- | --- |
| A / B 的公网映射 | |
| 打洞结果（成功 / 失败原因） | |
| 成功后探测次数与耗时 | |

> 两台机器在同一 NAT 后时，多数家用路由器不支持回环（hairpinning），失败属正常，换一台不同网络的机器再试。

## 2. 自建中继验证（跨网兜底）

机器 A（服务端，需放行该 UDP 端口）：

```powershell
node tools/relay-one-shot.cjs server 40000
```

机器 B 与 C（客户端）：

```powershell
node tools/relay-one-shot.cjs client <A的IP> 40000
```

两端各 10 轮心跳并互发消息，服务端每 10 秒打印统计。

| 要记录 | 结果 |
| --- | --- |
| 两端入会是否成功（端点 ID） | |
| 是否互相收到消息 | |
| 真实 RTT 中位 / 最大 / 抖动 / 丢包 | |
| 服务端转发包数与字节数 | |
| 六类丢弃计数是否非零 | |

> 中继**不加密载荷**，加密由上层安全通道负责；这条通路尚未接入会话流程，目前只能按脚本验证。

## 3. Steam 端到端（跨网免端口映射）

> ⚠️ 用**小号**。AppID 480 是 Valve 的测试 App，可能被判定滥用。

1. 两台机器登录**不同** Steam 账号，两端 AppID 都填 `480`
2. A：SESSION → Steam P2P → 房主，启动后记录 17 位 SteamID
3. B：加入者，填 A 的 SteamID 与本机入口端口，启动
4. B 上让客户端连 `127.0.0.1:<B 的入口端口>`，验证数据是否经 Steam 传输层到达 A

| 要记录 | 结果 |
| --- | --- |
| 两端是否都 running | |
| B 日志是否出现连接建立 | |
| 数据是否双向通过 | |
| NETWORK 页 Steam 状态 / 是否走中继 | |
| 退出后端口是否释放 | |

> 同一账号自连已知无效（Steam 返回错误 8 并断开），必须两个账号。

## 4. 本地中继跨机（端口映射 / 局域网）

1. A：房主，监听 `0.0.0.0`，把要分享的服务端口写进规则
2. B：用 A 的**内网 IP**（同网段）或**公网 IP + 映射端口**（已做映射）连接
3. 检查两端 `sessionId` 是否一致（一致即同一条加密会话）

| 要记录 | 结果 |
| --- | --- |
| 同网段是否成功 | |
| 跨网（已映射端口）是否成功 | |
| 两端 sessionId 是否一致 | |
| SESSION 页字节数/速率是否真实增长 | |
