## 3. UDP 中继设计

```
加入者机器：游戏客户端 --UDP--> 本机入口端口(joiner) --[12B头]--> 房主 relayPort(host) --per-client socket--> 本地游戏
           游戏客户端 <--UDP-- 本机入口端口(joiner) <------------ 房主 relayPort(host) <--- 本地游戏
```

1. **会话映射**：房主按加入者机器的 UDP 源地址建表，每个加入者一个独立的本地 UDP socket 与游戏通信。游戏因此看到多个不同源端口，每个加入者是独立玩家，不会串会话，有专门用例验证。
2. **逐包口令**：可选。开启后加入者在每个数据报前加 `12 字节 = "SHLU" + SHA256(口令) 前 8 字节`；房主用 `timingSafeEqual` 校验，失败即丢弃，不转发、不回包、计入 rejected。未设口令不加头，与 TCP 版策略一致。这不是加密：口令指纹可被截获，阶段 3 会替换。
3. **会话老化**：默认 60 秒 `clientIdleMs` 未收到任何数据报即回收对应 socket。每 5 秒扫描一次，定时器 `unref`，不阻塞进程退出。
4. **上限保护**：默认最多 16 个对端会话 `maxClients`，超出直接丢弃并记录 `rejected`。
5. **不重排、不重传、不改写载荷**：可靠性交给游戏协议本身，中继只做地址映射与转发。
6. **端口语义**：UDP 与 TCP 的「空闲端口」并不等价，本次实测撞上 Windows 保留端口段返回 `EACCES`。`checkPort` 按协议分别探测，`EACCES` 提示已改成「可能被系统保留或权限不足」。

## 4. 多端口批量启动

规则格式与配置里的 `ports[]`、界面文本域一致，每行 `协议,本地端口,远端端口`：

| 角色 | 第一列 localPort | 第三列 remotePort |
| --- | --- | --- |
| 房主 | 本地游戏端口，即转发目标 | 对好友开放的监听端口 |
| 加入者 | 本机入口监听端口 | 房主监听端口 |

- 一次最多 16 条规则，协议必须是 TCP 或 UDP。
- 启动前逐条预检监听端口，按协议绑定 + 连接探测。任何一条失败，整个会话不启动，已建立的通道全部回收，有专门用例验证不留残余通道。
- 同协议同监听端口重复直接拒绝，并指出是第几条规则。
- 环路保护：同一条规则里监听端口与转发目标相同、且目标是回环地址时拒绝启动。
- 启动后每条规则对应一条**通道**，界面与 IPC 快照中分别给出监听地址、目标地址、连接数、字节数、数据报计数。
- **邀请码 v2** 携带全部规则，加入者粘贴一次就能填好地址、口令与全部端口。旧的 v1 邀请码仍可解析，按单条 TCP 规则处理，有兼容用例。

实测数据：

- UDP 端到端：加入者 → 房主 → 游戏回声 → 原路返回，1200 字节数据报字节一致。
- 会话隔离：两个加入者同时连入时，游戏服务看到 **2 个不同源端口**，载荷互不串。
- 口令错误：数据报被丢弃，游戏服务**收不到**任何包，不是收到后再丢，且不影响已建立的正确会话。
- 老化：`clientIdleMs=120ms` 时会话被回收，随后同一端口再来数据报能重新建立会话。
- 批量回滚：批量启动中途失败后 `channels.length === 0`，且先前端口可重新绑定。

## 7. 双机 UDP 联调清单

房主：

1. `npm start` → 会话 → 房主 → 端口规则填两行 `TCP,2300,2301` 与 `UDP,2300,2301`，按游戏实际端口改。
2. 「检测这些端口」应全部空闲 → 「启动桥接」→ 状态 `RUNNING`，通道列表出现 2 条。
3. 「复制邀请信息」发给好友。防火墙弹窗需允许专用网络。

加入者：

4. 会话 → 加入者 → 粘贴邀请码 → 解析，地址/口令/两行规则自动填好 → 「启动桥接」。
5. 游戏客户端连 `127.0.0.1:2300`。房主 UDP 行的「包 ↑/↓」应开始增长，TCP 行的连接数应为 1。

| 现象 | 原因 |
| --- | --- |
| 报「UDP 端口 X 无法使用：可能被系统保留」 | 端口落在 Windows 动态端口排除范围，换端口，用 `netsh int ipv4 show excludedportrange protocol=udp` 查看 |
| 通道起来了但 UDP 包计数一直是 0 | 游戏没连本地入口端口，或游戏用的是 TCP |
| TCP 通、UDP 不通 | 防火墙只放行了 TCP，UDP 要单独放行 |
| 加入者日志「口令不匹配」 | 两端口令不一致，重新粘贴邀请码 |
