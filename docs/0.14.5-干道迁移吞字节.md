# 0.14.5 掉线修复：干道重挂时出站队列里的字节被整段丢掉

## 1. 结论

好友进 Minecraft 世界后几秒到几十秒必掉线、聊天框反复"加入了游戏 / 退出了游戏"，根因是**干道（Steam P2P 连接）断开重挂时，出站队列里"已经排好队但还没交给 Steam"的字节随旧连接一起消失**；而那条本机连接被新干道用「同一个流号 + 世代 + 1」原地复活继续收发，于是对端那条 TCP 可靠字节流中间少了一截。

修复：`network/egress-queue.cjs` 新增 `takePending()`（取出"确认前缀之外、从没交给 Steam"的帧），`network/steam-adapter.cjs` 新增 `retagFrame()`（跨世代补发时只改世代字段），并把**寄存 → 复活**两条路径接上；同时把关闭日志改成"谁动手谁留名"。

## 2. 现场证据

数据来源：`%APPDATA%\stronghold-link\startup.log`（房主 pid 40548，`2026-10-13T10:28:36Z` 起）与 1 Hz 诊断 `net-latency-host-2026-10-13T10-28-48-256Z.jsonl`（577 帧）。

| 指标 | 值 |
|------|-----|
| Steam Lobby / 干道 | 干道 1 条，从 `存活3s` 到 `存活528s 上行59008KiB 下行533KiB 残留0KiB` |
| 干道断开（另一局，同文件 `:318`） | `连接结束（对端关掉了这条 Steam 连接）理由=Relay received unexpected noconnection packet 本次连接=1189s Steam原因=5010（对端没有回应连接请求） 存活=1189s 上行=0KiB 下行=19504KiB` |
| 紧随其后 | `[session] [Steam] 干道断了，先把 2 条本机连接寄存 60 秒等新干道来接（原因：Steam 连接断开）` |
| 本机游戏流结束行 | 11 条全为 `流结束（本机游戏服务把这条件接关了）…` —— 关闭原因字符串是**硬编码**的，不区分"游戏侧关的"和"我们自己 destroy 的" |
| 背压看门狗 | 1 Hz 诊断里 `stalled` 全程 `false`，暂停总时长 139/577 s，最长 12 s ⇒ 掉线**不是** 30 s 看门狗误杀 |

| `dropped` 增量 | 只与"流刚结束"同时发生（对端还在发尾帧），是被误记账的收尾帧 |

## 3. 根因

| # | 置信度 | 位置 | 结论 |
|---|--------|------|------|
| ① | **已验证事实（会红的用例）** | `network/steam-adapter.cjs` 的 `parkPeerStreams()`（房主）/ `parkTrunkStreams()`（加入者） | 只把流对象（本机 socket）挪进 `orphanStreams`；`peer.out` / `egress` 里"还没交给 Steam"的帧既不转移也不标记，`dropPeer()` 把 peer 从表里摘掉后随之消失。回归用例 `test/steam-adapter.test.cjs` 里，修前报 `少了 30000 字节 … 26 !== 30026` |
| ② | **已验证事实** | 同文件 `adoptOrphan()` / `resumeOrphanStreams()` | 复活时只补发"寄存期间新收到的" `parkQueue`，**不补发断开那一刻还压在出站队列里的字节**，且补发不带新世代 ⇒ 对端按迟到帧丢弃 |
| ③ | **已验证事实** | 同文件 `schedulePeerReconnect()` | 重连前 `egress.clear(peer)`，把没交给 Steam 的字节整段清掉（旧注释"重发只会让对端收到重复字节"是错的：队列里只有没被 Steam 接受的字节） |
| ④ | **已验证事实** | 同文件两处 `handleStreamFrame` 的"未知流"分支 | `if (type !== TYPE.Reset) stats.dropped += 1;` 把迟到的 CLOSE/Window 也记成"丢了数据"，`dropped` 这个指标因此失真（现场排查时它被当成数据丢失的证据） |
| ⑤ | **已验证事实** | `electron/main.cjs` 的 `CONNECTION_END_KINDS` | 只有 5 个 kind；`流结束（…）` 的 kind/reason 在适配器里写死为"本机游戏服务把这条件接关了"，把我们自己的清理也说成游戏侧关闭 |

未证实的假设（本次不作为依据）：Steam 中继（`hkg`）自身的抖动比例；校园网每流上行上限。

## 4. 改动文件与功能

| 文件 | 功能 |
|------|------|
| `network/egress-queue.cjs` | 新增 `takePending(peer, ids)`：按队列 FIFO 取出确认前缀之外的帧（`ids == null` 连干道队列一起取），返回 `{ trunk, streams }`；已确认的前缀早被 `commit()` 出队，所以取出来的**一定没送达** |
| `network/steam-adapter.cjs` | 新增 `retagFrame(frame, streamId, generation)`：只改这条流的世代字段（偏移 9），其余字节原样 |
| `network/steam-adapter.cjs` | `parkPeerStreams()` / `parkTrunkStreams()` 寄存前 `takePending()` 并挂到 `stream.pendingFrames` |
| `network/steam-adapter.cjs` | `adoptOrphan()` / `resumeOrphanStreams()` 复活时先补发 `pendingFrames`（`retagFrame` 成新世代）、再补发 `parkQueue` |
| `network/steam-adapter.cjs` | `schedulePeerReconnect()` 用 `takePending()` 取代 `egress.clear(peer)`，剩下的接回 `peer.queue` |
| `network/steam-adapter.cjs` | 新增 `STREAM_CLOSE_KINDS` / `noteLocalClose()` / `noteLocalCloseFor()` / `streamCloseInfo()`；13 条关闭与清理路径各自留名（游戏侧 / 本机应用 / 对端 MUX / 干道 / 清理） |
| `network/steam-adapter.cjs` | 房主 socket `close` 加 `firstGone(stream)` 守卫；`destroyPeerStreams(peer, reason, kind)` 支持 kind，协议错乱报 `BadFraming` |
| `network/steam-adapter.cjs` | `stream-left` 事件追加 `by` / `paused` / `backlogBytes` / `steamBacklogBytes` |
| `electron/main.cjs` | `CONNECTION_END_KINDS` 补齐 15 个 kind 的中文说明；`流结束（…）` 一行追加 `发起方=` / `暂停=` / `本机待发=` / `Steam待发=` |
| `test/steam-adapter.test.cjs` | 新增 7 条回归（见 §6） |
| `test/egress-queue.test.cjs` | 新增 2 条（`takePending` 语义） |

### 4.1 关闭日志新口径

`stream-left` 现在带 `发起方`（`by`）：`游戏侧` / `本机应用` / `对端MUX` / `干道` / `清理`。kind 与含义：

| kind | 发起方 | 含义 |
|------|--------|------|
| `LocalServiceClosed` | 游戏侧 | 游戏服务端（或本机游戏客户端）自己关了这条连接 |
| `LocalClientClosed` | 本机应用 | 浏览器/游戏客户端自己关了这条本机连接 |
| `PeerStreamClosed` / `PeerStreamReset` | 对端MUX | 对端用 MUX CLOSE / RESET 关掉了这条流 |
| `TunnelAbort` / `LocalTunnelAbort` | 干道 | Steam 干道断了，这条流的尾字节没能送达 |
| `TunnelClosed` | 清理 | 干道/会话清理时收掉了这条流 |
| `BadFraming` | 清理 | 数据流格式不对，协议层收掉了这条流 |
| `MigrateExpired` | 清理 | 干道重挂超时，收掉了这条流 |
| `OverflowAborted` | 清理 | 待发积压超过上限，收掉了这条流 |
| `BackpressureAborted` | 清理 | 背压暂停后长时间无进展，收掉了这条流 |
| `SessionStopped` | 清理 | 会话已停止，收掉了这条流 |
| `ProtocolViolation` | 清理 | 协议违规，收掉了这条流 |

## 6. 测试

| 测试 | 钉住的东西 |
|------|-----------|
| 房主干道断开时压在出站队列里的字节，复活后必须接着送 | 本修复的核心；修前 `AssertionError: … 少了 30000 字节 … 26 !== 30026` |
| 加入者同场景（与房主同一套语义） | 两侧寄存/复活行为一致 |
| `takePending`：只取没交给 Steam 的帧 | 补发不重复 |
| `takePending`：流内 FIFO + 按流号过滤不动别的流 | 顺序不乱、不串流 |
| `retagFrame`：只改要跨世代重发的那条流 | 对端不误丢补发数据 |
| TCP 分段与合并读取（半个帧 / 两帧粘一起 / 本机分三次写） | 读取边界不是包边界；半帧一个字节都不许写进去；两个方向逐字节一致 |
| 背压暂停→恢复 | 暂停只是"先别生产"：不掐游戏连接、恢复后字节完整、`dropped === 0` |
| 重复清理（Close → Reset → 破干道） | 同一条流只出一条 `stream-left`、幂等、不误记账 |
| 关闭日志：游戏侧 / 对端 MUX / 我们清理 | 三种关法三种发起方 |
