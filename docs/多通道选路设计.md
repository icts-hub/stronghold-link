# 多通道选路与故障切换 · 设计

**状态：未实现。** 当前会话只建立一条通道；RouteManager 会算、会监控、会抛 `NETWORK_ROUTE_CHANGED`，但**切换动作不会重建会话通道**。
本文写清要改哪里、怎么测、怎么回滚，便于评审后再动代码。

## 1. 目标

会话同时维持主通道与备用通道；监控发现主通道劣化时，把备用提升为主，并重建数据面。

## 2. 为什么不能直接切

- 现有通道是**端口转发器**（本地中继 / Steam 桥接）：客户端已经连到本机入口端口，换通道意味着入口端口后面的上游连接要重建
- 本地中继内核**不提供按消息发送**：无法做包级探测，因此它只能当"可用性候选"，不能当"质量候选"
- 可做包级探测的只有 Stronghold Relay（有 PING/PONG 与真实 RTT）

结论：能真正参与质量选路的候选目前是**中继**；本地中继与 Steam 只能按可用性参与（例如"房主端口不可达时切到中继"）。

## 3. 影响面（要改的函数）

`network/session.cjs`：

| 函数 | 现状 | 需要的变化 |
| --- | --- | --- |
| `_openChannels()` | 按规则逐条建一条通道 | 支持"主 + 备"两条：先建主，再按需建备（备用不在邀请信息里暴露） |
| `_teardownChannels()` | 停掉所有通道 | 增加"只停某一条"，供切换时替换 |
| `getSnapshot()` | 每通道一份统计 | 增加 `route: { current, standby, state }` 字段（新增字段，不改既有字段） |
| `note()` | 写日志 | 复用：切换时写"路由切换：A → B" |
| 邀请码 `encodeInvite/parseInvite` | v1/v2 | **不动**：备通道由房主本地决定，不写进邀请码（避免协议破坏） |

`electron/main.cjs`：`session:start` 入参新增可选 `routePolicy`（默认关闭）；`network:route-watch` 在会话运行时的探测源改为读会话通道统计。

## 4. 切换流程（计划）

1. 主通道就绪 → RouteManager 记为 current
2. 备用通道就绪 → 记为 standby（**不暴露给客户端**，仅房主内部持有）
3. 监看发现主通道劣化且备用分数高出阈值 → 触发切换
4. 切换动作：把备用通道的监听端口"接管"为主入口（同一端口不能双绑 → 采用"先停主、再让备监听同端口"的顺序，中间有毫秒级中断）
5. 抛 `NETWORK_ROUTE_CHANGED`（已实现）+ 写会话日志（已实现）
6. **明确不承诺无缝迁移**：切换期间连接会断，客户端需要重连 —— 这点会写在 UI 与日志里

## 5. 测试计划

可在本机测（不依赖两台机器）：

- 开关默认关闭时，行为与现在**逐字节一致**（300 例既有测试必须全绿）
- 用注入的假通道验证切换顺序：先停主、再绑同端口、失败则回滚到原主通道
- 切换失败必须回滚且如实报错，不得留下"两条通道都停着"的空档
- `NETWORK_ROUTE_CHANGED` 与会话日志各出现一次，不重复
- 端口占用冲突、重复切换（冷却期）行为

需两台机器（写进跨机验证手册）：

- 真机上主通道劣化（拔网线/限速）后，备用是否接管成功、客户端重连耗时

## 6. 回滚方案

- 特性开关 `enableMultiChannel` 默认 `false`：关闭时**只建主通道**，代码路径与当前完全一致
- 开关打开但切换失败：自动回滚到原主通道并把错误写进会话日志（不静默）
- 影响面仅限 `session.cjs` 的通道生命周期 + `session:start` 入参与快照新增字段（IPC 只增不改）

## 7. 风险清单

| 风险 | 处理 |
| --- | --- |
| 同端口双绑失败 | 严格按"先停后绑"顺序，失败立即回滚 |
| 切换期间客户端断连 | UI 与日志明确写"连接会中断，需要重连"，不假装无缝 |
| 备用通道白占端口与带宽 | 备用只在策略允许时建立；默认不建 |
| 与邀请码协议冲突 | 备通道不写进邀请码，协议不动 |
| 既有测试被破坏 | 开关默认关闭 + 全量 300 例与 `--smoke` 作为门禁 |
