# Sacred Atlas｜纹样设计系统规范 1.1

## 0. 目标与边界

本系统将“神圣象征 × 自然生物 × 宗教建筑秩序 × 技术几何”统一为一种**精细蓝图线描语言**。它不是宗教素材贴图库，不是奇幻游戏魔法阵，也不是赛博朋克 HUD。

**实现边界：本包提供主题 tokens、SVG 装饰资源和可选 QML 装饰层，不替换产品页面。** 接入 Stronghold Link 时，原布局、控件几何、导航、键盘焦点、事件处理、状态模型、会话流程与 Steam P2P 网络实现必须保持不变。只有装饰层或现有背景/装饰元素可以变化。

## 0.1 PV 关键帧研究结果（本轮新增）

当前已直接检查用户上传的视频文件。全片约 4:34，以约 6 秒间隔抽样，并细看多个代表画面；具体时间码和观察见 `docs/VIDEO_FRAME_ANALYSIS.md` 与 `preview/PV-KEYFRAME-STUDY.jpg`。这不是逐帧运动追踪，所以只采用可验证的视觉结构，不臆测官方工程中的曲线和精确时长。

将 PV 视觉理解为**几种有层级的场景模式**，而不是把所有东西混成一张“宗教科技风”贴纸墙：

- **Blueprint / 主应用模式**：钴蓝平面、点阵、中心轴、圆环、技术引导线、鸟形轮廓和精确编号。Stronghold 默认优先使用此模式，并以用户鸟群截图作为轮廓及构图基准。
- **Sanctuary / 建筑模式**：纵向肋线、嵌套尖拱、轴对称空间、冰银与珍珠白。只适用于已有空白区域的低对比边缘装饰。
- **Ritual / 仪式模式**：单一环形中心、垂直光柱、少数放射线、厚重外框与大面积负空间。应用中只能保留其几何结构，不复制电影级光束与粒子场。
- **Editorial / 档案模式**：真实标题与小标签、分栏、竖向切片、矩形资料层级和强烈留白。不能因此改变 Stronghold 现有控件布局或文字内容。
- **High-contrast / 宣传模式**：PV 中的红黑白或黑白古铜强对比属于独立宣传版式，不作为应用默认皮肤，不覆盖常态联机界面。

### 从 PV 转译到 UI 的动态原则

宣传片使用快切、镜头移动、亮度冲击、纵向遮罩和多层叠合；桌面 UI 只取其“显现顺序”和“运动方向”，将幅度与速度显著降低：

- 鸟群只整体轻漂/慢移，路径原样，不做轮廓变形或随机扑翼。
- 圆弧、刻度和坐标只按几何阅读顺序短暂描绘。
- 圣徽旋转必须极慢或保持静止；状态变化不能让所有装饰同时启动。
- 主界面只允许一个主纹样系统加不超过两个辅助系统；页面切换时暂停离场页的装饰动画。
- reduced-motion 开启、页面隐藏或窗口最小化时停止非必要运动。
- 不将视频中的中文字幕、角色、官方标题字形或整帧构图作为可复用产品资产。

## 1. 基础视觉规格

### 色彩

- 纸面灰青 `#B7C4C2`：主参考画布；可以在现有底色之上做低对比度处理，不能未经确认把整个应用强行换肤。
- 亮纸 `#C7D2CF`、深纸 `#A6B5B5`：同色系层级，用于背景微差而非大渐变。
- 钴蓝 `#174EB4`：小面积锚点、路径和重点线条。
- 线稿蓝 `#2456A8`：鸟形、环线、建筑和主要几何轮廓。
- 深蓝 `#254B81`：少数层级文字与低频信息标记。
- 淡线蓝 `#6684B1`：远景辅助线、低对比度几何。
- 珍珠白 `#E4EAE5`、冰蓝 `#C6DDE2`：仅用于不破坏参考风格的局部对比。
- 香槟灰金 `#C7B68B`：仪式性稀有强调，单个视图覆盖面积不超过约 2%，不能变成金色主视觉。

### 描边、透明度、网格

在 1600 px 画布参考尺寸下，线宽：发丝线 0.65 px、次级 0.9 px、标准 1.25 px、强调轮廓 1.7 px；UI 控件自身线宽约 1 px，不能因纹样接入而加粗或改功能状态色。主要纹样不透明度 0.82，辅助几何 0.52，微型标记 0.42，氛围光环 0.14，背景鸟群 0.20。网格基准 24 / 48 / 96 px；所有标记对齐明确基线，禁止随意旋转到无规律角度。

## 2. 六大子系统

### S1 — 飞鸟与羽毛（主系统）

**造型规则**：优先使用 `assets/reference/bird-scene-original.png` 与 `bird-scene-transparent-overlay.png` 中来自用户截图的鸟群轮廓和线描；不可用通用 Font Awesome 鸟图标替换。独立姿态库 `assets/birds/bird-pose-library.svg` 是用于需要单只鸟的辅助原创形态，不宣称与截图中每一只鸟逐点一致。

- 主鸟：细长横向身体、短喙、清楚头部、翼尖分段、尾羽延伸；外轮廓比内部羽线略重。
- 六类姿态：展翼、滑翔、上升、侧飞、转向、远景简化。近景线宽 1.2–1.7；远景 0.6–0.9 且透明度 0.24–0.42。
- 鸟群路径：圆弧编队、对角疏密梯度、边缘汇入、主体外围绕行、射线方向展开。至少保留一块 25–40% 主区域作为负空间；避免均匀铺满。
- 鸟与技术线：鸟轮廓不得被网格压住；轨迹线穿越鸟群时降至 0.25–0.4 opacity；标记优先放于鸟与鸟之间的空处。
- 运动：整体群组慢漂 4–6 px / 22 秒往返；不同鸟若需独立动画，只可整体平移/旋转 1–2°、相位错开，不改变局部 path，不做骨骼扑翼。
- 禁止：卡通粗描边、填白实心鸟形、羽毛摄影素材、机械复制同尺寸同角度、强发光边缘、轮廓点逐帧变形。

### S2 — 光环与圣徽

资源：`assets/halos/halo-system.svg`、`assets/halos/radial-seal.svg`。

- 基础结构：同心圆半径比例遵守 1 : 0.90 : 0.75 : 0.46 : 0.38；外环点划，内环实线；圆心使用小十字或单点定位。
- 刻度：主刻度间隔 30°，次刻度间隔 6°；每第五个次刻度加长，不在每个圆周上堆满同样刻度。
- 分段环：只断开 2–4 段，用于强调方向或缺席状态；正常状态圆形保持完整。
- 动画：极慢旋转 90–120 秒一周，或单独描绘一段圆弧 0.9–1.8 秒；界面状态变化不应驱动整个圣徽不停旋转。
- 禁止：随机符号、伪文字、密集魔法阵、所有页面都放巨型圣徽。

### S3 — 羽翼与放射纹样

资源：`assets/wings/feather-fan.svg`。

- 主羽轴先定义扇形方向，再按角度排列羽片；外侧羽片更长，内侧较短；相邻羽片基线沿放射方向，而不是平行矩形。
- 羽片间保留 1–2 倍线宽的间隙；外轮廓更醒目，内部羽轴淡一档。
- 可用作页面边缘、角标底纹、转场残影，不可直接覆盖核心文字/控件。
- 动画只允许整体轻移、透明度渐变或按羽轴顺序描绘；不可随机飘羽。
- 禁止厚重角色翅膀、照片羽毛、实心白翅膀、强霓虹轮廓。

### S4 — 圣堂拱形与玫瑰窗

资源：`assets/architecture/rose-window-arch.svg`。

- 尖拱以中心轴对称；外/中/内三道拱间距保持近似恒定；柱线落在固定基线，玫瑰窗中心对齐主轴。
- 玫瑰窗采用 12 等分瓣形，内圈保留足够空隙；极简版本只保留八分或十二分几何，不在小尺寸塞入微小纹理。
- 适用主视觉边框、页面空白区或过场，不覆盖既有布局组件；必须随内容留白而裁切。
- 动画采用分层显现、单向透光或 1–2 px 的视差；不整页缩放。
- 禁止整座教堂照片、所有页面统一加拱形、尖拱直接穿过文字和点击区域。

### S5 — 神圣几何与技术坐标

资源：`assets/geometry/coordinate-geometry.svg`。

- 每个圆、弧、轴和交点必须有构图作用：定位鸟群路径、标记主轴、框定中心或建立尺度。
- 角度刻度按 6° / 30° 基准；多边形围绕同一中心；坐标轴与主视觉轴对齐。
- 标签必须是有意义的实际内容（如 SESSION INDEX、ROUTE STATE），业务数值应绑定真实模型；没有真实数据时使用中性构图标记，不能伪造延迟/连接数。
- 可动画化的部分限制为描边偏移、光点沿既定轨迹缓慢移动和单个标记淡入。
- 禁止满屏 HUD、随机数据、无意义公式、无主轴的图形叠加。

### S6 — 铭文、刻印与仪式标记

资源：`assets/inscriptions/ritual-markers.svg`。

- 文本使用真实字符串和项目现有字体；标签短、分组清晰，编号仅在有序列表/节点中使用。
- 结构由细框线、基线、短刻度、两端印记及中间标题组成；正文绝不伪装成古文字乱码。
- 所有状态词必须绑定真实状态，不得将静态 UI 假装为“CONNECTED”或“READY”。资产中的英文只用于设计预览，接入后替换为应用真实字段。
- 动画只沿排版阅读顺序淡入或描绘分隔线，不做逐字乱闪。

## 3. 四种组合模板

### A — 鸟群 + 圣徽 + 留白
资源：`assets/compositions/bird-seal-negative-space.svg`。一个光环作为次焦点，鸟群沿弧线从画面边缘进入；主 UI 内容区必须保持空净，环线避开标题和按钮。

### B — 羽翼 + 圣堂拱框
资源：`assets/compositions/wing-arch-frame.svg`。拱框负责竖向秩序，羽翼扇形为唯一主纹样；适合空白侧区或启动/过渡区域，不是新的页面框架。

### C — 鸟群 + 坐标轴 + 几何轨迹
资源：`assets/compositions/flight-coordinate.svg`。只让一条主要轨迹带动视觉；次级坐标透明度低于鸟线稿，适合网络状态/路径信息背景，但不得伪造网络指标。

### D — 玫瑰窗 + 放射几何 + 少量铭文
资源：`assets/compositions/rose-window-technical.svg`。玫瑰窗是主系统，铭文条为辅助；只用于原界面已有的大面积空白区，不新增卡片或面板。

每个视图最多一个主纹样系统 + 两个辅助系统；六大子系统不能同时抢主导。布局空间不足时删减装饰，不挤压控件。

## 4. 动态表现和性能

- 核心动画限定为 transform、opacity、SVG dash offset；不使用逐帧 JavaScript、循环 Canvas repaint 或粒子系统。
- 鸟轮廓不允许被变形，主鸟群只整体轻漂；halo 旋转周期 110 s；弧线绘制按几何顺序播放。
- 同时运动的群组最多 3 个；应用页面隐藏或窗口最小化时暂停；系统或项目提供 reduced-motion 时直接停动画并显示静止构图。
- 图片/矢量资源缓存；SVG 过密时静态栅格化用于背景层，但保留源 SVG；不对每帧进行路径重绘。

## 5. 项目接入规则

1. 先识别实际源代码和 UI 容器，记录现有控件坐标/尺寸/父子层级/信号槽。
2. 装饰层只插入现有背景宿主，`enabled: false`、不接收焦点、没有 MouseArea，置于控件之后。
3. 使用真实资源系统路径；不要凭假定写 qrc alias。
4. 不更改控件布局约束、tab 顺序、路由、文字、事件、view model、状态处理、后端和网络代码。
5. 在相同窗口尺寸和 DPI 下做前后截图差异比较；现有交互区域不得移动或被覆盖。

## 6. 负面清单

- 不要把本系统做成赛博朋克 HUD、魔法阵合集、卡通鸟、白鸽素材拼贴或金色奇幻海报。
- 不要全屏使用大光晕、玻璃模糊、发光描边或金属渐变。
- 不要随机旋转、随机缩放、随机散布；任何几何关系都要可解释。
- 不要假装访问了无法读取的视频镜头；逐帧分析以实际截图为凭。
- 不要为了“统一风格”改动产品原有布局与交互行为。
