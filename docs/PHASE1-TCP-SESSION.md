## 3. 数据流

```
房主：游戏服务(127.0.0.1:targetPort) <- tcp-relay host <- 监听 bindHost:relayPort <- 加入者
加入者：游戏客户端 -> 127.0.0.1:localPort -> tcp-relay joiner -> 房主 host:relayPort
渲染进程 -> preload(contextBridge) -> ipcMain -> SessionManager -> tcp-relay
主进程事件 -> webContents.send('session:event') -> preload.onEvent -> 界面状态/日志
```

## 4. 会话状态机

```
idle --start--> starting --ready--> running --stop--> stopping --> idle
                    |                                     ^
                    +--校验/绑定失败--> error -------------+ (可再次 start)
```

- `starting` / `running` 期间再次 `start` → 拒绝（`EALREADYRUNNING`），不会破坏正在运行的会话。
- `stop()` 幂等；`stop()` 在 `starting` 期间调用会先等这次启动结束。
- 退出路径（`before-quit`、`window-all-closed`）调用 `SessionManager.shutdown()`：同步销毁所有 socket 并关闭监听，保证「异常退出不留残余监听」。

## 5. 口令握手协议（中继层，游戏数据零改动）

两端都设置同一 `authToken` 时：

```
加入者 -> 房主:  "SHL1 <token>\n"
房主(连接本地游戏端口成功后) -> 加入者: "SHL1-OK\n"     然后双方开始透明转发
房主(口令错误/房间已满/目标不可达) -> 加入者: "SHL1-DENY <原因>\n"
```

- 未设置 `authToken` 时完全不握手，行为与旧版裸转发一致（向后兼容，已有测试覆盖）。
- 口令错误时，**加入者界面会显示房主给出的具体原因**（例如「口令不匹配」「房主本地游戏端口无响应」），而不是只看到断开。
- 该机制只用于防止误连到别人的中继；**不是加密**，明文仍可在链路上被抓取，阶段 3 会替换为真正的认证与加密。

## 6. 为什么端口检测要「绑定 + 连接」双重判断

Windows 允许 `0.0.0.0:P` 与 `127.0.0.1:P` 同时绑定（不像 Linux 直接 `EADDRINUSE`）。
如果只用「能不能 bind」判断，房主模式（默认 `0.0.0.0`）会误报端口空闲，实际流量却被旧进程截走。
所以 `session.checkPort()` 在绑定成功后还会主动连接一次：能连上就判定为「已被监听」。

## 7. IPC 契约

见 `README.md` 的表格。要点：

- 渲染进程只能调用固定频道；入参经过白名单 + 类型收紧（多余字段直接丢弃，已有测试验证不会污染原型）。
- 主进程把内部错误统一翻译成中文文案后再抛给界面（不会把 `EADDRINUSE` 与英文堆栈丢给用户）。
- 会话数据在渲染进程侧只读，界面不持有 socket。

## 10. 双机联调清单（请在两台电脑上执行）

准备：两台电脑在同一局域网（或同一 VPN），Windows 防火墙允许专用网络。

房主（A 机）：

1. `cd source && npm start`
2. 游戏库 → 选择/新增配置（例如 `TCP,2300,2301`：本地游戏端口 2300，中继端口 2301）
3. 会话 → 角色「房主」→ 监听地址 `0.0.0.0` → 确认端口 → 「检测端口」应提示空闲 → 「启动桥接」
4. 状态应为 `RUNNING`，`Listen` 显示 `0.0.0.0:2301`；如提示「本地游戏端口上没有检测到服务」，先启动游戏
5. 「复制邀请信息」，把内容发给 B

加入者（B 机）：

6. `cd source && npm start`
7. 会话 → 角色「加入者」→ 粘贴邀请码 → 「解析」（地址/端口/口令自动填好）→ 确认本地入口端口（如 2300）→「启动桥接」
8. 状态 `RUNNING`；若出现「暂时连不上房主」警告，检查 A 机防火墙、IP 是否同网段
9. 启动游戏客户端，连接 `127.0.0.1:2300`；A 机界面 `Live connections` 应变为 1，`Traffic` 开始增长

失败对照：

| 现象 | 可能原因 |
| --- | --- |
| 启动时报「端口已被监听」 | 上次会话没退干净，或其它程序占用；换端口或结束占用进程 |
| 加入者日志「房主拒绝了本次连接：口令不匹配」 | 两端口令不一致（重新复制邀请码） |
| 加入者日志「房主本地游戏端口无响应」 | A 机游戏服务没启动 / 端口填错 |
| 能启动但游戏连不上 | 游戏客户端连接的地址/端口不是本机入口端口；或游戏用的是 UDP（本版本不支持） |
| 只有本机能连 | 监听地址选了 `127.0.0.1`；或 Windows 防火墙拦截了入站 |
